# TyloInfer product Client

This private package contributes product UI to the official DSH Host. It does not replace the root, start a second React application, own a conversation, or change Agent Core.

## Shared Studio presentation

- `settings.launcher`: default-expanded inference controls above a separate Settings button. Settings opens through the official shell's `openSettings` action; all native settings sections and their lifecycle remain registered.
- `main`, key `tyloinfer.inference`: seven independently rendered inference pages. Overview shows connection, serving and hardware samples; Models separates artifacts and running instances and provides explicit load/unload, directory registration and native operation tracking; Service exposes the bounded runtime policies; Resources shows hardware, instance memory and filtered prefix inventory; Downloads shows actual executor capability, storage, queue and user-initiated Hub metadata; Analysis reuses Studio's architecture data and precision charts; Logs separates events, request samples and job records. Returning to chat selects the native conversation without creating or replacing a session.
- `shell.overlay`: top-right appearance controls for both blank and existing conversations, using the native theme service and persistence path. The controls hide on inference panels to avoid overlapping their actions.
- `sidebar.brand.mark` and `sidebar.brand.name`: the existing TyloInfer product mark and name replace the shell's fallback artwork. The same mark supplies the browser icon. A frame-layer title projection keeps native selected-session titles and changes only their product suffix.
- Product colors use the public theme token override API. The blank-home headline and decorative whale are hidden by product-scoped CSS, without replacing the native composer or workspace controls. Styles, browser icon, title projection and registrations are disposed with the plugin.
- The sidebar foot identifies `TyloInfer <version> based on DSH <version>`. TyloInfer's version is read from the core version source at build time; DSH's version is read from the running Host module manifest, not from the plugin compatibility declaration. An unavailable Host version is explicitly shown as unknown.
- Settings presentation is scoped by the plugin-owned body class and the native `data-shortcut-modal="settings"` marker. The product supplies its panel sizing, navigation treatment, compact appearance controls and narrow-screen layout without replacing `SettingsRoot`, its dynamic sections, native configuration forms, credentials handling or save/validation behavior. The pinned Host DOM structure is checked by the focused browser test; the scope class is removed when the plugin unloads.

All seven navigation entries use the original Studio icons and mapping. Page availability does not claim complete parity with every Studio control. The Client implements online model settings, deletion-plan confirmation, cache inventory/text/purge, original model browsing, download-directory configuration and bounded queue actions through the corresponding Host contracts. These require the matching Host methods to be mounted. Runtime clear/trim, registered-GGUF companion selection, safe endpoint metadata, terminal-job archival and globally scoped cache-directory changes now use fixed Host contracts and explicit confirmations. Remote routing, authentication mutation, listener changes, benchmarks and batch global-context reload remain outside the exposed controls. A deployment without download executors states that limitation and cannot submit a download. Native settings remain dynamic rather than a hardcoded product list.

The independent Studio remains a supported inference WebUI and desktop application; it does not depend on a DSH or Agent build. Its root opens inference, and its display preferences stay in its own browser settings layer without loading legacy Agent workspace or settings providers. The Client imports shared Studio presenters (`RuntimeHeroView`, `OverviewModels`, `OverviewEndpoints`, `MemoryBudgetControlsView`, `PrefixCacheControlsView`, `ModelAliasMappingView`, `InferencePolicyView`, `MemoryHierarchy`, `ServingStatisticsPanel`, `ResourceMonitorView`, `ResourceAllocationView`, `ModelLibrarySummary`, `LocalCheckpoints`, `ModelSettingsDialogView`, `ModelContextSettingsView`, `PrefixCacheInventoryView`, `ModelBrowserView`, `CommunityModelBrowserView`, `DownloadDirectoryView`, `AnalysisWorkspaceView`, `AnalysisPanels`, `RepositoryFiles`, `DownloadQueueView`, `LogDetailsView`) rather than maintaining reduced table-only replacements. Studio owns those presenters and its original design tokens and layouts. The Client scopes their CSS to its inference panel, supplies native translation/job snapshots and uses a native HTML dialog adapter without adding ReactDOM. The build rejects imports of the standalone API transport, runtime provider, router and notification store across this presentation boundary.

Numeric values use inherited text fonts with tabular, lining figures rather than a digits-only font substitution. Action controls share compact type size, line height and medium weight; identifiers and raw records retain monospace treatment. Both builds consume the same numeric and control typography styles.

Accepted model, model-context, memory-budget and download operations restore progress automatically within the same browser tab. Context reloads cannot be cancelled after submission; no cancellation control or RPC is invented for them. Restoration reads the native job and never resubmits the operation. The UI does not ask for operation IDs. If a write loses its response before receiving a job ID, the browser preserves an outcome-unknown marker rather than silently replaying it. Browser storage can be unavailable or cleared; recovery is not a claim of cross-device or full Host-restart history synchronization.

### Remaining Studio parity gaps

These are unfinished migration work, not equivalent replacements for the original controls:

| Models | Next-load and online context/KV/YaRN/residency controls, directory/files and deletion confirmation reuse Studio components. The embedded companion picker accepts only complete registered GGUF artifact IDs; the core resolves files and the loader checks compatibility. Client paths are rejected. Controlled browser data is not real-weight or companion-loader validation. |
| Service | The original automatic/manual budgets, RAM/SSD controls, alias dialog, MTP switch and global next-load context controls are shared. Cache-directory changes use core directory IDs and separately confirm possible reload/KV loss across all loaded models. | Resources | The original allocation summary and hierarchy share the current usable-pool calculation, not nominal device capacity. Five-second sampling retains successful values with an explicit stale warning after read failures and stops on navigation. Monitoring, prefix overview and inventory/filter/block presenters are shared. Text reads require privacy confirmation; namespace/all purge preserves scoped and partial results. Runtime clear targets an explicit instance and discloses service-wide image-cache release; trim explicitly sets the retained hot-cache limit. Real maintenance writes are not validated by browser fixtures. |
| Downloads | Full official/community browsers, metadata, precision/file selection, model cards, directory controls and queue are shared. The original card grid owns its alignment, without a panel-wide button centering rule. Initial entry, reentry and page refresh read the fixed local-only official snapshot; a missing route is an error, never a fallback to network metadata. Empty caches are explicit. Local download-directory, executor and queue snapshots update every five seconds, pause while hidden and stop on navigation; read failures retain successful data and disable actions until recovery without replacing form drafts. Real archival writes are not validated by browser fixtures. |

The independent Studio's desktop validation is separate. Neither presenter reuse nor passing bounded browser tests means all seven pages have full visual and behavioral parity.

## Host seam

The Client calls bounded Connection RPC on `/tyloinfer`: `core/read` with named resources and filters; fixed `models`, `operations`, `service`, `downloads` and `hub` methods for the corresponding actions. Artifact, loaded-model and instance inventories are separate. Rejected or malformed reads remain errors, not fabricated empty inventories. Page mounts, refreshes, navigation and ticket restoration do not write or contact a Hub. Model load/unload, file downloads, service policies, cache maintenance and terminal-job archival require explicit scoped confirmation. Cache-directory changes disclose their global reload and active-KV effects. Accepted model or memory tickets are not completion, and cancellation requests are not cancelled jobs. Transport failure after a write blocks further submissions as outcome-unknown; no write is retried automatically. Leaving a page aborts its reads, not its background operation. The Host owns the independently configured inference service and credentials; the Client contains no fixed core endpoint or credential.

A missing bridge is displayed as an error, never as invented model statistics. Building or testing this package is not evidence that a full Host mounted it.

## Build and checks

From this package, after installing the repository's Studio development dependencies:

```sh
node build.mjs
node --test tests/plugin.test.mjs tests/core-runtime.test.mjs tests/model-management.test.mjs tests/model-load-options.test.mjs tests/page-api.test.mjs tests/job-events.test.mjs tests/product-boundaries.test.mjs
```

The build uses the monorepo's Vite toolchain and emits a single lazy `window.__ModuleLoader__.load` factory. React is provided by the Host's `require('react')`; no React runtime or ReactDOM root is bundled. The source uses APIs present in React 18.2. The current Node contract smoke uses Studio's development React and verifies factory loading, slot registration, default markup, navigation callbacks and disposal. The isolated official Host browser check also covers native rendering, settings persistence, same-session draft retention during inference navigation, refresh recovery and narrow-screen settings. These checks validate the currently exposed bounded workflows, not every standalone Studio control, real-weight inference, real downloads or final visual acceptance by the user.

The bare package row in `cordis.patch.yml` carries both Host and Client halves. The Host export deliberately has no business implementation. Compatibility is currently limited to the pinned `0.2.2-rc.2` DSH release; broader compatibility is not claimed. Publication or installation in the user's running DS Bot profile is not part of this work.
